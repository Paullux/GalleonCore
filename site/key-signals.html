GalleonCore

The pipe: lighting single keys from another program

GalleonCore can light single keys for other programs (an assistant, a calendar, a script) without those programs ever touching the keyboard: galleond stays the only program that writes to it. This is “the pipe”. A program says “F3 pulses orange for ten minutes”; it never learns anything about the keyboard in return. Status: tested by the author on Linux and Windows 11 with the command-line tool; not yet confirmed with other people’s programs. The same text, in more detail, is kept in the repository as docs/KEY_SIGNALS.md.

Opening the pipe

The pipe is closed by default. The person opens it in Bosun (Keyboard tab, live lighting): tick “Other programs may light keys”. The choice is written by Bosun alone and read by galleond; a program cannot change it. Unticking it takes every signal away within a second. Nothing here works while the live lighting is off, and nothing here switches it on.

What a program can and cannot do

  • It sends a colour for one key, for a time it chooses (1 second to 24 hours, mandatory: a signal always has an end), steady or pulsing.
  • It never receives anything about the keyboard: not which keys are pressed, not what is lit, not even the list of its own signals. There is no event, no property and no reply that says more than “accepted” or why not.
  • The signals are drawn over the person’s lighting, at the brightness in force (dark during “lights off until morning”), and they all end when the live lighting stops.
  • Limits: 8 programs, 16 signals per program, 64 in all, 20 requests per second together. Two programs on the same key: the last one to ask wins, and the other comes back when it leaves.
  • key is the name of the physical key as on a QWERTY keyboard: F3, Left Control, and W for the key engraved Z on an AZERTY keyboard. A key whose LED has not been measured yet is refused; nothing is guessed.

Linux: D-Bus

On the session bus: service org.galleoncore.Deck, object /org/galleoncore/KeySignals, interface org.galleoncore.KeySignals. Three methods, no property, no signal.

MethodArgumentsReturns
Setkey s, red, green, blue i (0 to 255), effect s (steady or pulse), seconds d (1 to 86400)an empty string when accepted, else why not
Clearkey strue if this program had a signal on that key
ClearAll—true if this program had any signal

Your program has to stay on the bus. A signal belongs to the D-Bus connection that asked for it and goes when that connection closes. A command that makes one call and exits (busctl, gdbus, dbus-send) therefore lights nothing that lasts. Keep the connection open for as long as the signals should last. The seconds you give are the longest they can last, not a promise that they stay if your program leaves. Signals are private to their connection: a program cannot take away another’s.

Windows: the local endpoint

Windows has no D-Bus. galleond’s per-user local endpoint, a named pipe \\.\pipe\galleoncore-<24 hex digits>, takes the same three requests: one JSON object per line, one request per connection. The 24 digits are the first 24 hexadecimal digits of the SHA-256 of the UTF-8 text of the current user’s SID. It is reachable by that user only.

{"action":"key-signal","client":"assistant","key":"F3","red":255,"green":120,"blue":0,"effect":"pulse","seconds":600}
{"action":"key-signal-clear","client":"assistant","key":"F3"}
{"action":"key-signal-clear-all","client":"assistant"}

Differences, by the nature of this endpoint: no reply about the result (it answers {"ok":true} for a well-formed request, whether or not a key was lit); no way to tell programs apart (a signal belongs to the client name in the request, 1 to 64 plain characters, so another program of the same person who knows it can clear it); no cleanup when a program quits: only the end of the duration or a clear removes a signal, so choose short durations and renew them.

The command-line tool

galleon-key-signal is installed with GalleonCore (bin/), on Linux and Windows. It lights one key, or several given together (--key F3,F4,F5), through the interface above and reads nothing from the keyboard. It is also the simplest way to try the pipe, and Bosun has a “Try a signal” panel for the same purpose.

galleon-key-signal --key F3 --color "#ff7800" --effect pulse --seconds 600
galleon-key-signal --key F3 --red 255 --green 120 --blue 0 --seconds 60
galleon-key-signal --key F3,F4,F5 --color "#ff7800" --seconds 60

Put the colour in double quotes: in bash and PowerShell a bare # starts a comment.

On Linux it stays running while the key is lit (the signal belongs to its connection) and takes the signal away at the end of the time or when stopped (Ctrl-C, kill). Exit status: 0 as asked, 1 wrong command line, 2 galleond refused (the reason is printed) or could not be reached. On Windows it sends the request and ends at once; --clear --key F3, --clear-all and --client NAME exist there, and it says “Sent” without any word on the lighting.

What never comes back

No key press, no key order, no frequency, no current colour, no list of signals, no history: nothing on this pipe lets a program reconstruct what the person types. This is a rule of the project, not a detail: see “Security and privacy by design” in AGENTS.md.

Le tuyau : allumer des touches seules depuis un autre programme

GalleonCore peut allumer des touches seules pour d’autres programmes (un assistant, un agenda, un script) sans que ces programmes touchent jamais au clavier : galleond reste le seul programme qui y écrit. C’est « le tuyau ». Un programme dit « F3 pulse en orange pendant dix minutes » ; il n’apprend rien du clavier en retour. État : essayé par l’auteur sous Linux et Windows 11 avec l’outil en ligne de commande ; pas encore confirmé avec les programmes d’autres personnes. Le même texte, plus détaillé, est dans le dépôt : docs/KEY_SIGNALS.md (en anglais).

Ouvrir le tuyau

Le tuyau est fermé par défaut. La personne l’ouvre dans Bosun (onglet Clavier, éclairage en direct) : cocher « Les autres programmes peuvent allumer des touches ». Le choix est écrit par Bosun seul et lu par galleond ; un programme ne peut pas le changer. Le décocher retire tous les signaux dans la seconde. Rien ne marche tant que l’éclairage en direct est éteint, et rien ici ne l’allume.

Ce qu’un programme peut et ne peut pas faire

  • Il envoie une couleur pour une touche, pour une durée de son choix (de 1 seconde à 24 heures, obligatoire : un signal a toujours une fin), fixe ou pulsée.
  • Il ne reçoit jamais rien du clavier : ni les touches pressées, ni ce qui est allumé, pas même la liste de ses propres signaux. Il n’y a ni événement, ni propriété, ni réponse qui en dise plus que « accepté » ou pourquoi non.
  • Les signaux sont dessinés par-dessus l’éclairage de la personne, à la luminosité en vigueur (noirs pendant « éteint jusqu’au matin »), et tous s’arrêtent quand l’éclairage en direct s’arrête.
  • Limites : 8 programmes, 16 signaux par programme, 64 en tout, 20 demandes par seconde pour tous ensemble. Deux programmes sur la même touche : le dernier demandeur l’emporte, l’autre revient quand il part.
  • key est le nom de la touche physique comme sur un clavier QWERTY : F3, Left Control, et W pour la touche gravée Z sur un clavier AZERTY. Une touche dont la LED n’a pas encore été mesurée est refusée ; rien n’est deviné.

Linux : D-Bus

Sur le bus de session : service org.galleoncore.Deck, objet /org/galleoncore/KeySignals, interface org.galleoncore.KeySignals. Trois méthodes, aucune propriété, aucun signal.

MéthodeArgumentsRetour
Setkey s, red, green, blue i (0 à 255), effect s (steady ou pulse), seconds d (1 à 86400)une chaîne vide si accepté, sinon la raison
Clearkey svrai si ce programme avait un signal sur cette touche
ClearAll—vrai si ce programme avait un signal

Votre programme doit rester sur le bus. Un signal appartient à la connexion D-Bus qui l’a demandé et part quand elle se ferme. Une commande qui fait un appel puis sort (busctl, gdbus, dbus-send) n’allume donc rien de durable. Gardez la connexion ouverte aussi longtemps que les signaux doivent durer. Les secondes données sont le maximum, pas une promesse qu’ils restent si votre programme part. Un signal est privé à sa connexion : un programme ne peut pas retirer celui d’un autre.

Windows : le point d’accès local

Windows n’a pas de D-Bus. Le point d’accès local par utilisateur de galleond, un tube nommé \\.\pipe\galleoncore-<24 chiffres hexadécimaux>, prend les trois mêmes demandes : un objet JSON par ligne, une demande par connexion. Les 24 chiffres sont les 24 premiers chiffres hexadécimaux du SHA-256 du texte UTF-8 du SID de l’utilisateur courant. Seul cet utilisateur peut l’atteindre.

{"action":"key-signal","client":"assistant","key":"F3","red":255,"green":120,"blue":0,"effect":"pulse","seconds":600}
{"action":"key-signal-clear","client":"assistant","key":"F3"}
{"action":"key-signal-clear-all","client":"assistant"}

Différences, dues à la nature de ce point d’accès : aucune réponse sur le résultat (il répond {"ok":true} pour une demande bien formée, qu’une touche ait été allumée ou non) ; aucun moyen de distinguer les programmes (un signal appartient au nom client de la demande, 1 à 64 caractères simples, donc un autre programme de la même personne qui le connaît peut l’effacer) ; pas de nettoyage quand un programme se ferme : seule la fin de la durée ou un effacement retire un signal, donc choisissez des durées courtes et renouvelez-les.

L’outil en ligne de commande

galleon-key-signal est installé avec GalleonCore (bin/), sous Linux et Windows. Il allume une touche, ou plusieurs données ensemble (--key F3,F4,F5), par l’interface ci-dessus et ne lit rien du clavier. C’est aussi le moyen le plus simple d’essayer le tuyau, et Bosun a un panneau « Essayer un signal » pour la même chose.

galleon-key-signal --key F3 --color "#ff7800" --effect pulse --seconds 600
galleon-key-signal --key F3 --red 255 --green 120 --blue 0 --seconds 60
galleon-key-signal --key F3,F4,F5 --color "#ff7800" --seconds 60

Mets la couleur entre guillemets doubles : dans bash et PowerShell, un # seul commence un commentaire.

Sous Linux il reste en vie tant que la touche est allumée (le signal appartient à sa connexion) et retire le signal à la fin du temps ou à l’arrêt (Ctrl-C, kill). Code de sortie : 0 comme demandé, 1 ligne de commande fausse, 2 galleond refuse (la raison est affichée) ou injoignable. Sous Windows il envoie la demande et sort aussitôt ; --clear --key F3, --clear-all et --client NOM y existent, et il dit « Sent » sans rien dire de l’éclairage.

Ce qui ne revient jamais

Aucune touche pressée, aucun ordre de touches, aucune fréquence, aucune couleur actuelle, aucune liste de signaux, aucun historique : rien sur ce tuyau ne permet à un programme de reconstituer ce que la personne tape. C’est une règle du projet, pas un détail : voir « Security and privacy by design » dans AGENTS.md.

Die Leitung: einzelne Tasten von einem anderen Programm beleuchten

GalleonCore kann für andere Programme (einen Assistenten, einen Kalender, ein Skript) einzelne Tasten beleuchten, ohne dass diese Programme die Tastatur je berühren: galleond bleibt das einzige Programm, das darauf schreibt. Das ist „die Leitung“. Ein Programm sagt „F3 pulsiert zehn Minuten lang orange“; es erfährt nichts über die Tastatur zurück. Stand: vom Autor unter Linux und Windows 11 mit dem Kommandozeilenwerkzeug getestet; mit Programmen anderer Personen noch nicht bestätigt. Derselbe Text, ausführlicher, liegt im Repository: docs/KEY_SIGNALS.md (englisch).

Die Leitung öffnen

Die Leitung ist standardmäßig geschlossen. Die Person öffnet sie in Bosun (Tab Tastatur, Live-Beleuchtung): „Andere Programme dürfen Tasten beleuchten“ anhaken. Die Wahl wird nur von Bosun geschrieben und von galleond gelesen; ein Programm kann sie nicht ändern. Entfernt man den Haken, verschwinden alle Signale innerhalb einer Sekunde. Nichts funktioniert, solange die Live-Beleuchtung aus ist, und nichts hier schaltet sie ein.

Was ein Programm darf und was nicht

  • Es sendet eine Farbe für eine Taste, für eine selbst gewählte Dauer (1 Sekunde bis 24 Stunden, Pflicht: ein Signal hat immer ein Ende), konstant oder pulsierend.
  • Es erhält nie etwas von der Tastatur: nicht welche Tasten gedrückt werden, nicht was leuchtet, nicht einmal die Liste der eigenen Signale. Es gibt kein Ereignis, keine Eigenschaft und keine Antwort, die mehr sagt als „angenommen“ oder warum nicht.
  • Die Signale werden über die Beleuchtung der Person gezeichnet, mit der aktuellen Helligkeit (dunkel während „Licht aus bis zum Morgen“), und alle enden, wenn die Live-Beleuchtung stoppt.
  • Grenzen: 8 Programme, 16 Signale je Programm, 64 insgesamt, 20 Anfragen pro Sekunde zusammen. Zwei Programme auf derselben Taste: das zuletzt anfragende gewinnt, das andere kommt zurück, wenn es geht.
  • key ist der Name der physischen Taste wie auf einer QWERTY-Tastatur: F3, Left Control, und W für die auf einer AZERTY-Tastatur mit Z beschriftete Taste. Eine Taste, deren LED noch nicht gemessen wurde, wird abgelehnt; nichts wird erraten.

Linux: D-Bus

Auf dem Session-Bus: Dienst org.galleoncore.Deck, Objekt /org/galleoncore/KeySignals, Schnittstelle org.galleoncore.KeySignals. Drei Methoden, keine Eigenschaft, kein Signal.

MethodeArgumenteRückgabe
Setkey s, red, green, blue i (0 bis 255), effect s (steady oder pulse), seconds d (1 bis 86400)leere Zeichenkette bei Annahme, sonst der Grund
Clearkey swahr, wenn dieses Programm ein Signal auf dieser Taste hatte
ClearAll—wahr, wenn dieses Programm ein Signal hatte

Ihr Programm muss auf dem Bus bleiben. Ein Signal gehört zur D-Bus-Verbindung, die es angefragt hat, und endet, wenn sie sich schließt. Ein Befehl, der einen Aufruf macht und endet (busctl, gdbus, dbus-send), beleuchtet daher nichts Dauerhaftes. Halten Sie die Verbindung so lange offen, wie die Signale dauern sollen. Die angegebenen Sekunden sind das Maximum, kein Versprechen, dass sie bleiben, wenn Ihr Programm geht. Signale sind privat für ihre Verbindung: ein Programm kann die eines anderen nicht entfernen.

Windows: der lokale Endpunkt

Windows hat kein D-Bus. Der lokale Endpunkt von galleond pro Benutzer, eine benannte Pipe \\.\pipe\galleoncore-<24 Hexziffern>, nimmt dieselben drei Anfragen an: ein JSON-Objekt pro Zeile, eine Anfrage pro Verbindung. Die 24 Ziffern sind die ersten 24 Hexziffern des SHA-256 des UTF-8-Textes der SID des aktuellen Benutzers. Nur dieser Benutzer erreicht ihn.

{"action":"key-signal","client":"assistant","key":"F3","red":255,"green":120,"blue":0,"effect":"pulse","seconds":600}
{"action":"key-signal-clear","client":"assistant","key":"F3"}
{"action":"key-signal-clear-all","client":"assistant"}

Unterschiede, bedingt durch diesen Endpunkt: keine Antwort zum Ergebnis (er antwortet {"ok":true} auf eine wohlgeformte Anfrage, ob eine Taste leuchtete oder nicht); Programme sind nicht unterscheidbar (ein Signal gehört zum client-Namen der Anfrage, 1 bis 64 einfache Zeichen, ein anderes Programm derselben Person, das ihn kennt, kann es löschen); keine Bereinigung beim Beenden eines Programms: nur das Ende der Dauer oder ein Löschen entfernt ein Signal, wählen Sie also kurze Dauern und erneuern Sie sie.

Das Kommandozeilenwerkzeug

galleon-key-signal wird mit GalleonCore installiert (bin/), unter Linux und Windows. Es beleuchtet eine Taste oder mehrere gemeinsam angegebene (--key F3,F4,F5) über die obige Schnittstelle und liest nichts von der Tastatur. Es ist auch der einfachste Weg, die Leitung auszuprobieren; Bosun hat dafür das Feld „Ein Signal ausprobieren“.

galleon-key-signal --key F3 --color "#ff7800" --effect pulse --seconds 600
galleon-key-signal --key F3 --red 255 --green 120 --blue 0 --seconds 60
galleon-key-signal --key F3,F4,F5 --color "#ff7800" --seconds 60

Setze die Farbe in doppelte Anführungszeichen: In bash und PowerShell beginnt ein einzelnes # einen Kommentar.

Unter Linux läuft es weiter, solange die Taste leuchtet (das Signal gehört zu seiner Verbindung), und entfernt das Signal am Ende der Zeit oder beim Beenden (Strg-C, kill). Exit-Status: 0 wie gewünscht, 1 falsche Kommandozeile, 2 galleond lehnt ab (der Grund wird ausgegeben) oder ist nicht erreichbar. Unter Windows sendet es die Anfrage und endet sofort; dort gibt es --clear --key F3, --clear-all und --client NAME, und es sagt „Sent“, ohne etwas über die Beleuchtung zu sagen.

Was nie zurückkommt

Kein Tastendruck, keine Tastenreihenfolge, keine Häufigkeit, keine aktuelle Farbe, keine Signalliste, kein Verlauf: nichts auf dieser Leitung erlaubt einem Programm, zu rekonstruieren, was die Person tippt. Das ist eine Regel des Projekts, kein Detail: siehe „Security and privacy by design“ in AGENTS.md.

La tubería: iluminar teclas sueltas desde otro programa

GalleonCore puede iluminar teclas sueltas para otros programas (un asistente, un calendario, un script) sin que esos programas toquen nunca el teclado: galleond sigue siendo el único programa que escribe en él. Esa es «la tubería». Un programa dice «F3 pulsa en naranja durante diez minutos»; no averigua nada del teclado a cambio. Estado: probado por el autor en Linux y Windows 11 con la herramienta de línea de comandos; aún no confirmado con programas de otras personas. El mismo texto, más detallado, está en el repositorio: docs/KEY_SIGNALS.md (en inglés).

Abrir la tubería

La tubería está cerrada por defecto. La persona la abre en Bosun (pestaña Teclado, iluminación en directo): marcar «Otros programas pueden iluminar teclas». La elección la escribe solo Bosun y la lee galleond; un programa no puede cambiarla. Al desmarcarla se retiran todas las señales en un segundo. Nada funciona mientras la iluminación en directo esté apagada, y nada aquí la enciende.

Lo que un programa puede y no puede hacer

  • Envía un color para una tecla, durante un tiempo que elige (de 1 segundo a 24 horas, obligatorio: una señal siempre tiene un final), fija o pulsante.
  • Nunca recibe nada del teclado: ni qué teclas se pulsan, ni qué está encendido, ni siquiera la lista de sus propias señales. No hay evento, propiedad ni respuesta que diga más que «aceptada» o por qué no.
  • Las señales se dibujan sobre la iluminación de la persona, con el brillo vigente (oscuras durante «apagado hasta la mañana»), y todas terminan cuando la iluminación en directo se detiene.
  • Límites: 8 programas, 16 señales por programa, 64 en total, 20 peticiones por segundo entre todos. Dos programas en la misma tecla: gana el último que la pide, y el otro vuelve cuando este se va.
  • key es el nombre de la tecla física como en un teclado QWERTY: F3, Left Control, y W para la tecla grabada con Z en un teclado AZERTY. Una tecla cuyo LED aún no se ha medido se rechaza; no se adivina nada.

Linux: D-Bus

En el bus de sesión: servicio org.galleoncore.Deck, objeto /org/galleoncore/KeySignals, interfaz org.galleoncore.KeySignals. Tres métodos, ninguna propiedad, ninguna señal.

MétodoArgumentosDevuelve
Setkey s, red, green, blue i (0 a 255), effect s (steady o pulse), seconds d (1 a 86400)una cadena vacía si se acepta, si no el motivo
Clearkey sverdadero si este programa tenía una señal en esa tecla
ClearAll—verdadero si este programa tenía alguna señal

Su programa tiene que seguir en el bus. Una señal pertenece a la conexión D-Bus que la pidió y termina cuando esa conexión se cierra. Un comando que hace una llamada y sale (busctl, gdbus, dbus-send) no ilumina, por tanto, nada duradero. Mantenga la conexión abierta mientras deban durar las señales. Los segundos indicados son el máximo, no una promesa de que sigan si su programa se va. Las señales son privadas de su conexión: un programa no puede quitar las de otro.

Windows: el punto de acceso local

Windows no tiene D-Bus. El punto de acceso local por usuario de galleond, una tubería con nombre \\.\pipe\galleoncore-<24 dígitos hexadecimales>, acepta las mismas tres peticiones: un objeto JSON por línea, una petición por conexión. Los 24 dígitos son los 24 primeros dígitos hexadecimales del SHA-256 del texto UTF-8 del SID del usuario actual. Solo ese usuario puede alcanzarlo.

{"action":"key-signal","client":"assistant","key":"F3","red":255,"green":120,"blue":0,"effect":"pulse","seconds":600}
{"action":"key-signal-clear","client":"assistant","key":"F3"}
{"action":"key-signal-clear-all","client":"assistant"}

Diferencias, por la naturaleza de este punto de acceso: ninguna respuesta sobre el resultado (responde {"ok":true} a una petición bien formada, se haya encendido una tecla o no); no distingue los programas (una señal pertenece al nombre client de la petición, de 1 a 64 caracteres sencillos, así que otro programa de la misma persona que lo conozca puede borrarla); sin limpieza al cerrarse un programa: solo el fin de la duración o un borrado retira una señal, así que elija duraciones cortas y renuévelas.

La herramienta de línea de comandos

galleon-key-signal se instala con GalleonCore (bin/), en Linux y Windows. Ilumina una tecla, o varias indicadas juntas (--key F3,F4,F5), por la interfaz anterior y no lee nada del teclado. También es la forma más sencilla de probar la tubería, y Bosun tiene un panel «Probar una señal» para lo mismo.

galleon-key-signal --key F3 --color "#ff7800" --effect pulse --seconds 600
galleon-key-signal --key F3 --red 255 --green 120 --blue 0 --seconds 60
galleon-key-signal --key F3,F4,F5 --color "#ff7800" --seconds 60

Pon el color entre comillas dobles: en bash y PowerShell un # suelto empieza un comentario.

En Linux sigue en marcha mientras la tecla está encendida (la señal pertenece a su conexión) y retira la señal al terminar el tiempo o al detenerlo (Ctrl-C, kill). Código de salida: 0 como se pidió, 1 línea de comandos incorrecta, 2 galleond rechaza (se muestra el motivo) o no responde. En Windows envía la petición y termina de inmediato; allí existen --clear --key F3, --clear-all y --client NOMBRE, y dice «Sent» sin decir nada de la iluminación.

Lo que nunca vuelve

Ninguna pulsación, ningún orden de teclas, ninguna frecuencia, ningún color actual, ninguna lista de señales, ningún historial: nada en esta tubería permite a un programa reconstruir lo que la persona escribe. Es una regla del proyecto, no un detalle: véase «Security and privacy by design» en AGENTS.md.
